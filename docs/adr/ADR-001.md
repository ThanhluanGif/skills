# ADR-001: Selection of File-Based Hierarchical Compaction over SQL/Docker

- **Status:** APPROVED
- **Date:** 2026-07-27
- **Deciders:** Principal Solution Architect & User

---

## CONTEXT
During early development, Docker containers and PostgreSQL/Prisma database schemas were created for fullstack deployment. However, for a lightweight, zero-friction AI Skill Framework, running Docker and SQL services locally created unnecessary infrastructure overhead and environment dependencies.

## DECISION
We decided to **eliminate Docker and SQL database dependencies completely** from the core skill framework repository. Instead, we implemented a 3-Tier File-Based Hierarchical Compaction Engine (`data/cards.json` -> `data/milestones/` -> `data/reports/`).

```mermaid
graph LR
    RawCards["10 Cards (cards.json)"] -->|Compaction Engine| Milestone["1 Milestone (data/milestones/)"]
    Milestone -->|Executive Summarizer| MasterReport["1 Macro Report (data/reports/)"]
```

## PROS
1. **Zero Infrastructure Overhead**: Runs 100% natively on Node.js with zero external dependencies.
2. **Context Window Optimization**: Keeps active card files lightweight (<10 cards) to avoid prompt token bloating.
3. **High Portability**: The skill repository can be cloned or copied as a single lightweight folder.

## CONS
1. High-concurrency ACID transactions require locking mechanisms on JSON files.

## ALTERNATIVES CONSIDERED
- PostgreSQL + Prisma ORM (Rejected due to setup complexity for local CLI skill users).
- SQLite (Considered, but JSON/Markdown provides direct human readability).
